# 产品规格

本文件保留早期产品设想，用于追溯需求来源。当前已实现的业务边界以[共享应用契约](app-contract.md)为准；其中通知为可选，持续有货不重复提醒，凭据存于应用 SQLite 数据库。

理光监控为个人用户提供本地运行的库存提醒。用户完成简短引导后，程序按时间计划自动检查所选商品，通过用户配置的渠道发送消息。本文件规定早期设想的可见行为；技术结构见[技术设计](architecture.md)，验证方法见[测试规范](testing.md)。

## 一、范围

首版关注一台设备上的监控与通知，所有配置和历史保存在本机。macOS 与 Windows 共用六页桌面界面，Linux 提供交互式配置和常驻运行能力。

### 1.1 平台与运行（R01）

macOS 通过安装后的应用运行，主窗口关闭后继续监控，菜单栏提供打开窗口、开始或暂停、状态摘要和退出。第一次关闭窗口说明后台运行方式。退出应用终止监控；再次打开遵循用户保存的运行意愿和时间计划。暂停状态跨重启保留。

同一配置目录同一时间由一个监控实例持有。桌面重复启动打开已有窗口，CLI 重复运行提示已有实例。不同配置目录不在首版普通界面中暴露为多实例功能。

Linux 支持前台运行、终端中断和 systemd 服务。交互式配置成功后可立即以前台方式开始；注册开机服务是单独的明确操作。真实 Linux 的安装、重启和无桌面运行属于发布必测项。

### 1.2 产品边界（R02）

监控请求使用匿名商品接口，字段范围由理光接口适配器定义。个人登录 Cookie、Bearer、OpenID、设备登录标识与抓包会话信息不进入请求。通知凭据及代理凭据限于各自目的地。

商品接口是外部依赖，服务端可能改变字段或认证要求。无法解析时显示接口异常并保留旧数据的时间，不伪造库存。无登录请求仍会暴露网络出口等信息，文档和界面不承诺账号不可关联或永久可用。

## 二、引导

首次使用引导承担最小配置和实际验证。高级参数默认隐藏，引导中的商品列表和通知表单复用日常页面的组件及业务校验。

### 2.1 三步主流程（R03）

第一步“选择商品”：显示内置或在线发现的产品列表，名称旁标注 Product ID 和目录验证时间。用户至少选择一个产品，也可手工输入 Product ID。网络正常时验证所选产品的返回结构；目录不可用时说明原因，允许保存进度和重试。批量扫描放在高级入口，不作为首次使用的必经步骤。

第二步“接收通知”：Mac 默认推荐系统通知，用户主动点击后请求系统权限，并发送带测试标记的通知。引导说明系统专注模式等可能影响显示，用户确认是否看见。也可以配置第三方渠道并执行一次真实测试。Linux 需要至少一个测试通过的第三方渠道。

第三步“确认并开始”：展示所选产品、有效通知、时间计划、时区、请求节奏和当前网络模式。用户可展开修改时间计划；高级代理与速率参数仍可稍后设置。点击“完成并开始”保存正式配置及运行意愿，随后自动进入状态页，无需再次点击开始。

时段内开始正常监控；时段外显示“已设置，将于……开始监控”。引导中的连接验证由用户操作触发，可以在计划时段外进行，验证结果不产生库存上架通知。这样用户既能验证配置，又能理解正式监控的下一次启动时间。

### 2.2 完成与恢复（R04）

成功完成引导要求至少一个当前配置下验证有效的产品和一个有效通知渠道。系统权限拒绝时提供打开系统设置和配置第三方渠道的入口。第三方测试通过表示平台接受消息；系统通知权限允许及用户确认看见测试消息用于首次引导确认，后续依然不能保证用户阅读。

通知或网络暂时无法验证时可保存草稿并退出，界面明确“设置尚未完成”。重开恢复草稿，不自动启动监控。修改通知凭据或网络设置会使相关测试结果失效；完成按钮之前再核对有效配置版本。产品连接验证距完成超过五分钟时重新执行一次验证。

完成后的普通启动直接进入状态页。恢复默认设置重新进入引导，重置前明确展示将清除的配置和凭据范围；操作后监控保持停止。中途崩溃恢复草稿，原有完整配置保持可用。

## 三、页面

六页共享同一份运行状态和配置。保存成功与运行生效分别展示，失败时保留用户输入并说明具体字段和可采取的操作。

### 3.1 状态（R05）

运行状态区显示监控中、部分异常、计划时段外、已暂停、未完成配置或已停止。运行状态和数据新鲜度分别表达：进程存活不代表请求成功。

产品行显示名称、产品标识、可用状态、库存记录、最近成功时间、数据年龄及当前错误。预期检查失败且没有更新的成功结果时标记数据过期；暂停或计划时段外明确标记未更新，并继续显示数据年龄。页内展示实际发出请求速率、成功速率、有效通知数量、代理最近可用数量和重要日志。速率统计窗口固定为最近六十秒，刚启动时注明采样不足。

基本操作为开始、暂停、恢复、重启监控和测试通知。重启监控取消旧任务后重建任务，保留历史状态和未完成通知。运行错误不触发无限重启；重试策略遵循第四部分。所有网络测试也纳入请求统计。

### 3.2 通知（R06）

系统通知提供启停和权限状态；第三方列表提供新建、编辑、测试、启停与删除。渠道名称、平台、订阅事件、最近测试和最近发送结果均可查阅。相同平台可建立多个命名渠道。

配置页面根据提供商展示必要字段，提供外部教程链接。飞书、企业微信与钉钉各自验证平台业务结果；HTTP 成功状态不足以认定测试成功。钉钉可用接入方式由第一阶段实测确定，尚未验证的接入方式不得展示为可直接启用。

默认订阅有货、持续监控失败和恢复事件，重复有货提醒默认关闭。高级设置允许为单渠道开启仍有货提醒，并设置间隔；该设置不会增加库存请求。编辑关键字段后渠道进入待测试状态，旧配置不继续悄悄发送。测试未通过时其他已启用渠道继续工作。

停用或删除渠道阻止后续发送并取消其排队通知；已经被平台接收的消息无法撤回。新建渠道不会自动补发过去的库存事件，用户可通过测试或明确查询当前状态获得确认。

### 3.3 速率（R07）

提供工作日、每天、自定义星期，按北京时间展示时间窗口及下一次开始时间。默认值集中在第四部分。首版固定使用北京时间（UTC+08:00）；实现中的 IANA 时区标识为 `Asia/Shanghai`。所有界面、日志和通知显示带偏移的北京时间。

请求间隔及实际节奏见[共享应用契约的监控方案](app-contract.md#监控方案)。

连续失败等待按每条线路计算；商品持续失败通知按有效监控时间内没有成功结果的时长计算。计划时段外和手动暂停期间冻结失败计时，恢复时重新开始失败观察窗口；网络中断但监控应在运行时继续计时。多个有效出口中任意一个成功即可恢复该商品监控健康。

### 3.4 代理池（R08）

支持带可选认证的 HTTP、HTTPS、SOCKS5 地址，允许批量导入。导入结果逐项说明格式问题，地址相同的条目按完整连接参数比较并提示重复。代理测试使用目标接口及响应解析，测试成功后可启用。

状态包括待测试、可用、冷却、自动停用和手动停用。展示成功率、请求耗时、连续失败次数与下一次可重试时间。冷却状态到期后先测试再恢复，不立即补发积压请求；自动停用需要用户手工重新测试启用。

直连、系统代理和代理池为互斥监控模式。代理池模式使用启用且可用的出口，不隐含额外直连线路。无可用代理时暂停网络请求并显示原因。第三方通知默认使用直连或用户选择的系统代理，独立于库存代理池。

### 3.5 监控产品（R09）

支持产品发现、手动添加、勾选启停和移除。产品目录记录 Product ID、名称、最近验证时间和来源；规格及 SKU 字段以接口验证结果为准。SKU 语义验证完成前，以产品粒度监控和展示。

优先使用经验证的目录接口，另提供有限 ID 范围扫描。扫描由用户主动发起，显示进度、错误和已发现产品，支持暂停、继续和取消。扫描按检查点保存进度；中断后由用户选择继续。扫描缺口不代表商品目录结束，扫描结果不声称覆盖所有 SKU。

刷新目录保留用户勾选。移除产品取消该产品请求及未发送的库存通知，保留有限历史记录。添加产品先验证再参与监控；单个无效产品不阻止其他产品运行。

### 3.6 其他设置（R10）

提供检查更新、项目主页、教程、反馈、网络模式、登录后启动、打开日志目录和恢复默认设置。macOS 与 Windows 的开机选项明确写成“登录后启动”，默认关闭；Linux 的开机常驻通过明确的服务安装步骤完成。

导出配置默认排除凭据，导入后缺少凭据的渠道保持待配置。恢复默认设置清除产品选择、渠道、代理、凭据及运行设置，保留有限历史供排错；用户另行勾选“同时清除历史”时才删除历史。诊断报告允许预览后保存。反馈可打开 GitHub Issue 草稿或系统邮箱；无邮件程序时支持复制内容。提交由用户确认，程序不自动发布日志。

## 四、规则

以下是首版执行规格。尚未经过实测的性能数值属于设计默认值或验收目标，不能用来宣传已达到的能力。

### 4.1 默认与限制（R11）

默认每天 09:00 至 19:00，北京时间（UTC+08:00，IANA 时区标识 `Asia/Shanghai`）。时间窗口采用开始包含、结束不包含；跨午夜窗口按开始日期的星期归属，开始等于结束视为无效输入。墙上时间用于计划，单调时钟用于请求间隔和超时。

请求默认配置和值域由 `MonitorConfig::default()` 与 `MonitorConfig::validate()` 定义。间隔允许为零；每条产品与出口线路串行运行，并遵守服务端冷却。

普通线路连续三次失败后等待三十秒。代理连续三次可归因的连接失败冷却一小时，到期测试再次失败计为第四次并再次冷却一小时，累计到第五次连续失败自动停用；成功才清零，冷却到期不清零。代理专用规则优先于普通等待，目标接口的 429、认证或结构错误不累计为代理连接失败。

单商品连续十分钟有效监控时间无成功结果发送一次失败提醒，下次有效结果发送一次恢复提醒。程序启动后尚未成功的商品从首次计划检查开始计时。正常启动不批量发送“恢复”。

有货重复提醒默认关闭；用户启用后的间隔须至少一分钟。通知总超时十秒，单条最多尝试三次，失败后分别等待十秒、六十秒；提供商要求更长等待时遵循其要求。库存提醒超过五分钟不再重发，转为过期记录；失败和恢复提醒超过一小时不再重发。发送前核对事件是否仍适用及渠道是否仍启用。

扫描默认配置由 `MonitorConfig::default()` 定义，扫描自身节奏与共享准入见[共享应用契约](app-contract.md#监控方案)。一次扫描最多一千个连续 ID；更大范围由用户分次选择。

### 4.2 库存事件（R12）

理光详情响应的 `data.storeInfo.isShow` 数值为 1 表示上架、数值为 0 表示未上架；未上架即使库存字段为正数，仍判定无货。仅在 `isShow` 为 1 且 `data.storeInfo.stock` 是大于零的数值时判定有货。库存为 0 或负数时判定无货；所需字段缺失、类型不符或 `isShow` 不是 0／1 时视为接口异常。未知、无货、有货为库存状态，数据过期为独立属性。

从无货变为有货产生上架事件，覆盖已上架商品由零库存变为正库存的情况。首次启用一个从未成功监控过的产品，若发现有货，产生明确标注的“首次检查发现有货”事件。连续有货结果不重复产生上架事件。

运行错误和暂停不改写最近有效库存状态。恢复后有效结果与最近有效状态比较，保留采样间隔说明；无法观察的空档不推断库存变化时间。重启恢复数据库状态，持续有货不产生新的首次事件。

多出口结果归并到同一产品状态。已应用较晚发起的有效响应后，更早发起的响应不再更新库存；失败响应不会阻止较早但尚未被有效响应取代的结果。请求排序无法证明服务端缓存新鲜度，界面显示本机检查时间。

### 4.3 运行变更（R13）

保存配置时校验整次变更，成功后生成新的配置修订号。界面展示实际应用的修订号，保存失败保留旧配置。取消勾选、暂停、进入非监控时段时取消相关在途请求，旧任务的迟到结果不再更新状态或产生通知。

减少速率立即约束新请求，调整产品或代理仅重建受影响线路。请求下一次执行按当前时间重新排定，不追赶错过的周期。已经生成的有效库存通知在计划结束后仍可在有效期内发送；暂停监控也保留这些通知，渠道停用另按通知页规则处理。

网络断开、DNS 故障或目标限流进入错误处理流程，进程继续运行。429 的 Retry-After 对整个目标域名生效；无法解析等待值时至少等待六十秒，不通过其他代理继续绕过这次目标冷却。401、403 或结构错误显示接口异常，降低检查频率到至少六十秒一次，不触发自动反复重启。

### 4.4 资源与隐私（R14）

日志最多保留五个文件，每个约 10 MiB；UI 保留最近五百条事件。数据库重要历史保留最近三十天且最多一万条，先达到的限制生效。已终结通知计入历史限制；待发送通知最多一千条，达到上限时库存状态仍更新，记录并在状态页明确提示被省略的通知数量。

数据清理每小时及启动时运行，按有限批次处理。网络响应解码后最多一 MiB，超出作为响应异常；错误摘要限制长度，原始响应及凭据不写日志。统计保留最近二十四小时的分钟汇总，过期删除。用户配置随用户增删保留，不受历史清理误删。

诊断采用允许导出的字段集合，包括版本、系统、匿名化错误摘要和资源统计。排除 Webhook、令牌、代理认证、个人路径、原始请求与数据库文件。截图和微信窗口信息不属于诊断内容。

## 五、验收

平台行为和运行质量共同决定发布条件，不能以“页面已完成”替代监控正确性。

### 5.1 系统与恢复（R15）

macOS 菜单栏、通知权限、登录启动及睡眠恢复必须在真实机器上验证。睡眠期间不承诺监控，唤醒后重算计划并按限额恢复。Linux 服务验证开机启动、异常退出后的受限重启和正常停止。配置不可读时显示明确错误，禁止静默恢复成默认配置运行。

### 5.2 发布与反馈（R16）

发布包和更新包来自公开项目的构建流程。Mac 更新经用户确认，在停止请求并保存状态后安装；检查失败保留现有版本。凭据不参与公开构建。Linux 首版使用发行包替换及服务重启，保留数据目录，不让运行中进程自行覆盖二进制。

最低支持系统版本与 CPU 架构依据平台试验确定，发布页面列出实测范围。Windows 桌面版交付 NSIS 安装程序，并完成系统托盘、通知、登录启动与实际运行的原生验收。Mac 正式分发需要签名、公证及更新签名的实际验证，未具备时清楚标注测试包安装限制。

### 5.3 长期运行（R17）

以模拟网络连续运行十天检查内存、连接、文件描述符、数据库和日志增长；加速时钟测试用于业务时序，真实时间耐久测试用于资源稳定性。两者分别记录。真实外网验证保持低频，不以持续高频请求第三方接口作为压力测试。

通过标准和测量方法在测试规范中定义，所有尚未实测的结果保持待验证。首版交付应能从首次引导走到真实通知，也应能解释断网、无通知权限和计划时段外的状态。
