# 测试规范

本文件保留早期验收设想，用于追溯测试范围。当前实现和验收边界以[共享应用契约](app-contract.md)及现行代码测试为准；下文关于重复有货提醒、Keychain、socket 和凭据文件的场景不再是现行验收项。

本文件把[产品规格](specification.md)中的需求转成可重复验证的场景。测试编号标识验收要求，执行结果另存记录。平台验证覆盖 macOS、Windows 桌面版与 Linux CLI。

## 一、方法

开发遵循规格、失败测试、最小实现、重构、回归的顺序。一个阶段交付前必须能证明目标行为在实现前失败、实现后通过，同时记录尚需真实平台验证的部分。

### 1.1 测试层次

核心规则使用 Rust 单元测试与临时 SQLite，注入可控时钟、确定性随机源和网络结果。HTTP 集成测试启动本地模拟服务，覆盖真实超时与取消、响应大小、重定向、代理连接和提供商业务错误。

界面组件用 Vitest 和组件测试工具检查表单、错误提示及状态变化；浏览器测试适合验证页面流程，但不能代替 Tauri 的系统能力。Mac 安装包测试检查实际通知、Keychain、菜单栏和权限体验；Linux 使用真实系统或虚拟机测试 CLI、socket 与 systemd。

UI 测试通过可访问名称与字段语义定位。快照图片仅在布局或状态呈现值得检查时使用，不把整页像素一致作为业务正确性的主要依据。

### 1.2 记录与证据

每次执行记录命令或人工步骤、测试编号、代码修订、环境、开始结束时间、预期与实际结果，以及经过脱敏的证据路径。结果为通过、失败或未执行。网络实测需记录目标和请求量，禁止把跳过写为通过。

持续集成执行单元、HTTP 集成、配置与数据库测试、UI 组件测试及两平台构建。系统通知、公证、睡眠与重启验收单独签署。没有 Linux 执行环境时保持未验证，不以 Mac 上编译成功替代。

## 二、引导

引导测试首先验证用户能完成真实配置，同时避免草稿和正式运行混淆。以下 Given、When、Then 分别表示准备、动作和可观察结果。

### 2.1 正常流程（T01，对应 R03、R04）

Given 新配置目录、可用产品响应和 Mac 已允许通知，When 用户选择产品、看到测试通知并确认、点击完成，Then 引导标记与正式配置在一次事务保存，状态页打开；计划内发出正式请求，计划外显示准确下一次开始时间。用户无需第二次启动操作。

用 Linux 重复流程，系统通知选项不可选，第三方业务测试成功才满足通知条件。引导两种入口必须得到语义一致的配置。

### 2.2 中断与异常（T02，对应 R03、R04）

Given 用户配置到第二步，When 退出或模拟崩溃后重开，Then 草稿恢复且没有正式监控请求。Given 已完成应用，When 再次打开，Then 直接进入状态页，保留运行意愿。

通知权限拒绝、提供商 HTTP 成功但业务失败、网络离线、目录不可用、所有产品验证失败均逐项测试：显示正确原因和恢复入口，保存草稿可用，完成按钮说明缺少条件。拒绝系统权限后配置有效第三方渠道可以继续。

修改已测试凭据或网络配置、验证过期、测试过程中再次编辑字段，均不得沿用不对应当前修订的成功结果。模拟完成事务提交前后崩溃，恢复结果只能是完整草稿或完整正式配置。

### 2.3 非计划时间（T03，对应 R03、R07、R11）

Given 北京时间晚间完成引导，When 用户执行连接测试，Then 测试请求被计数但不产生有货提醒。完成后准确等待下次计划；进入计划后首次正式检查产生符合规格的首次有货事件。

覆盖周末关闭、跨午夜按开始日期归属、开始结束边界、开始等于结束无效输入，以及主机本地时区不同的情况。午夜附近显示和调度必须使用同一时区。

## 三、核心

核心测试使用可控响应精确制造并发、失败和重启时序。业务条件应写成断言，避免只验证函数执行未报错。

### 3.1 库存与通知（T04—T07）

T04 对应 R12。分别输入 `isShow=0` 且库存为正数、`isShow=0` 且库存为零、`isShow=1` 且库存为零、`isShow=1` 且库存为正数、缺少库存、非法类型、其他 `isShow` 数值与解析错误，核对库存及健康状态。输入无货→有货→有货序列，每渠道只登记一次上架事件；已上架零库存→正库存同样触发。网络错误后保持上次有效状态和过期提示。

T05 对应 R12、R13。晚发请求先成功、早发请求后返回，旧结果不覆盖新值；晚发请求失败、早发请求有效，早发有效响应仍可在未被新有效响应取代时应用。多个出口同时有货，事件数量保持一。暂停、取消产品或变更代次后的响应不产生事件。

T06 对应 R06、R12。在状态变更与通知写入事务的各个边界模拟退出，重启后既不丢失已提交事件，也不凭空产生重复首次事件。测试发送中断后结果未知的记录和重试，确认不宣称严格一次。

T07 对应 R06、R11、R14。一个渠道超时不阻塞其他渠道和商品请求。覆盖平台业务失败、错误认证、提供商限流、过期消息、渠道编辑／停用／删除、重试次数、重复提醒开关与间隔。通知队列满时仍更新库存并展示省略计数，已终结记录按保留规则清理。

### 3.2 调度与异常（T08—T11）

T08 对应 R07、R11。四产品中一个请求延迟，其余产品继续独立请求并处理结果。核对同线路在途数量、全局并发、全局发送速率、错峰、随机间隔边界和公平性。所有产品的就绪任务有限，不因长期拥堵建立无限待执行队列。故意超长响应不得引发追赶式补发。

T09 对应 R11、R13。通过本地 HTTP 服务持续悬挂连接，达到超时后确认实际连接或请求已取消、许可已释放。连续重复后服务端活动请求数、客户端任务数和文件描述符恢复至稳定范围，防止“上层超时、底层继续运行”。

T10 对应 R07、R11、R13。DNS 不存在、连接失败、TLS 错误、429、401、403、非 JSON、超过响应大小和结构变更分别触发正确分类，监控进程存活。目标级 429 冷却期间所有出口与扫描都停止发送，Retry-After 秒值及日期值均测试。普通网络恢复后重新检查，既无紧密重试，也无无限进程重启。

T11 对应 R07、R11。单线路失败而另一出口成功时不产生商品失联通知；持续无成功达到阈值才触发一次，随后成功产生一次恢复。计划外和暂停时间按规格处理，正常启动不批量发送恢复消息。实际请求率统计包含失败和测试请求，成功率另外计数。

### 3.3 产品与代理（T12—T14）

T12 对应 R09。扫描包含存在、缺失和错误响应的 ID 范围，缺失不提前终止范围；暂停、取消、继续正确保存检查点，错误扫描不删除现有产品。扫描与正式监控共用限额，正式监控优先。手动添加重复产品、非法 ID 和超过范围上限输入均有明确结果。

T13 对应 R08、R11。代理连接连续失败到冷却阈值、到期测试继续失败至停用阈值、成功重置计数分别验证。冷却到期不清除计数。目标 429、认证和结构异常不累计代理连接失败。重启保留冷却及手工停用状态，手工测试成功后才能重新启用。

T14 对应 R02、R08。模拟 HTTP、HTTPS 和 SOCKS5 代理，验证实际请求经过所选出口，凭据只传给正确代理。直连／系统代理／代理池互斥，池空时无隐含直连。商品请求中不存在个人 Cookie、Bearer、OpenID 和抓包标识；跨域重定向被拒绝。通知认证不泄漏到商品请求或诊断。

### 3.4 存储与配置（T15—T17）

T15 对应 R09、R13。修改产品、时段、速率和渠道后配置保存并有生效确认；重启后勾选和暂停状态保持。保存非法配置、数据库只读、磁盘写入失败时保留原配置并显示真实错误，不能默默运行默认配置。

T16 对应 R14。制造超出保留期、条数和日志容量的记录，执行清理后历史满足限制且待发送任务仍可用。UI 日志窗口有界、响应体大小有界，统计桶过期。数据库 checkpoint 后 WAL 不无限增长。数据库文件复用空间与持续增长分别判断。

T17 对应 R04、R10。恢复默认设置有范围确认，完成后停止监控并回到引导。配置导出不含凭据，重新导入后缺少认证的渠道不会变成有效。引导草稿、正式配置和历史互不误删。

## 四、平台

真实系统测试关注安装、权限和生命周期。环境版本和 CPU 架构写进执行记录，每个受支持组合都有证据。

### 4.1 macOS（T18—T20）

T18 对应 R01、R05、R15。安装应用后走完整引导，关闭窗口至少跨越多个请求周期仍有状态更新；菜单栏可以查看与暂停，重复启动打开已有实例。退出后无残留监控请求，重新运行保留用户状态。

T19 对应 R06、R10、R15。首次通知许可、拒绝后重新开启、专注模式、Keychain 保存和读取失败、登录启动开关逐项测试。应用使用通知能力时不要求辅助功能或屏幕录制。手动登录启动实测需要可中断的测试时段，避免影响用户当前工作。

T20 对应 R07、R08、R15。睡眠跨越开始或结束时间、唤醒时离线、切换网络、主机时区与时间变化分别验证。系统代理包括手动代理和 PAC；不支持的形式明确提示，不能静默直连。恢复后无补发风暴，数据年龄准确。

### 4.2 Linux（T21—T22）

T21 对应 R01、R03、R15。在真实 Linux 或 Linux 虚拟机中，无 GUI、无桌面 Keyring 环境完成 setup、通知测试和前台运行。Ctrl+C 有界退出，凭据文件权限正确，重复运行拒绝第二实例。CLI 在线配置通过 socket 生效，离线配置受相同锁保护。

T22 对应 R01、R13、R15。安装 systemd 服务后验证启动、停止、重启、异常退出与重启限额，以及机器重启后的恢复。测试用户服务退出登录条件和实际服务环境中的代理设置。纯 JSON 输出可解析，stderr 与 stdout 不混杂，异常 socket 请求不会导致服务退出。

### 4.3 Windows（T26—T28）

T26 验证 Windows x86_64 安装与生命周期。在 Windows 虚拟机内安装 NSIS 安装包，完成首次引导并开始、暂停、恢复和停止监控。关闭主窗口后检查任务仍按用户意愿运行；从系统托盘重开窗口，重复启动回到已有实例。退出和再次启动后，商品、配置、暂停意愿与历史保留。记录 Windows 版本、安装包路径和实际请求数量。

T27 验证 Windows 系统适配。登录启动状态能够读取；启用后在当前用户登录时启动已安装的应用，停用后重启虚拟机验证自动启动已取消。日志目录和 HTTP／HTTPS 链接分别由资源管理器与默认浏览器打开，含空格与中文的路径正常工作。系统通知测试在 Windows 通知中心可见，突出提醒覆盖屏幕、可用 Esc 关闭，关闭后不重复揭示已确认事件。

T28 验证共享业务与 Windows 构建。使用同一份 Rust Core、Svelte 界面和共享契约运行核心、前端与桌面原生测试，生成 Windows 安装程序并实际运行。常规行为测试沿用可控制的本地 HTTP 服务，真实理光请求单独记录；第三方通知在测试账号或明确授权的渠道执行。虚拟机的桌面功能验收、真实硬件性能和长期运行分别记录证据。

### 4.4 发布与反馈（T23—T24）

T23 对应 R16。在独立应用标识下验证签名、公证、更新包有效签名、无效签名拒绝、下载中断和用户取消。升级后配置、Secret 引用和库存状态保留。数据库升级失败能够恢复备份。Linux 替换二进制再重启后使用原数据正常运行。

T24 对应 R02、R10、R14。用虚构凭据、Webhook 查询参数、带认证代理和个人路径生成报告，检查这些内容未出现在导出中。用户能够预览、保存并打开 Issue 草稿；应用不自动提交。没有邮件程序的环境仍可复制反馈内容。

## 五、耐久

长期测试观察实际资源变化；加速业务时间不能证明真实进程运行十天后的资源表现。

### 5.1 十天测试（T25，对应 R17）

在 Mac 和 Linux 分别运行本地模拟目标与通知服务。按日循环注入稳定库存、库存变化、响应乱序、DNS 或连接错误、429、渠道超时和配置增删。配置规模固定并记录，重复添加删除代理以观察客户端释放。

预热后每分钟采样进程 RSS、活动请求、连接／文件描述符、排队任务、通知积压、日志字节和 SQLite／WAL 大小。GUI 进程与 Rust 后台分别记录。采样结果必须覆盖实际十天，提前结束按实际时长记录。

验收要求为进程持续可响应、无未处理异常、无数量超过配置上限的队列与请求、日志和历史清理按时完成。在重复相同负载并回到静稳状态后，第十天静稳 RSS 中位数相对第一天同等窗口增长不超过较大者：20% 或 30 MiB；超出必须分析对象或连接保留原因并修复后重测。该阈值是调查及验收门槛，不是内存泄漏不存在的数学证明。

预热后三次相同负载循环结束时，任务数和文件描述符应回到可解释的稳定区间。应用界面空闲与关闭窗口各有样本，避免把 WebView 常驻内存误认成业务队列泄漏。绝对包体积、RSS 和启动时间记录实测值，不预设宣传数字。

### 5.2 需求覆盖与放行

R01 由 T18、T21、T22 验证；R02 由 T14、T24 验证；R03 与 R04 由 T01—T03、T17 验证；R05 由 T11、T18 验证；R06 由 T06、T07、T19 验证；R07 由 T03、T08、T11、T20 验证；R08 由 T13、T14、T20 验证；R09 由 T12、T15 验证。

R10 由 T17、T19、T24 验证；R11 由 T03、T07—T11、T13 验证；R12 由 T04—T06 验证；R13 由 T05、T10、T15、T22 验证；R14 由 T07、T16、T24 验证；R15 由 T18—T22 验证；R16 由 T23 验证；R17 由 T25 验证。
