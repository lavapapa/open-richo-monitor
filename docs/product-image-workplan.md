# 商品资料与监控统计约定

核心提供商品资料、图片来源和监控统计，界面负责呈现与交互。布局、图片底座和字号以当前 DESIGN.md 与页面样式为准；验收覆盖真实商品名称、价格、累计时长和失败状态。

## 一、数据契约

字段回归样本位于 crates/core/tests/fixtures，保留解析测试所需的商品资料字段。`data.storeInfo.id` 必须与请求 productId 一致；主图使用 `image`，图集使用逗号分隔的 `sliderImage`，商品价格使用 `price`。详情可展示商品编号 `productNo`、计量单位 `unitName`，会员卡可展示 `isMemberCard` 和 `memberCardDays`。`otPrice` 和活动价格不赋予原价或优惠语义。描述 HTML 与 SKU 购买规则不进入主界面。

核心层保存展示所需的元数据，使用字段相等比较决定更新。每次成功监控响应刷新这一事实，网络失败保留最近成功数据，成功响应中缺失的可选字段清为空。元数据解析异常不影响有效库存字段。图片下载独立运行，当前仅展示和缓存 API 主图；图集 URL 保存为元数据，本轮未加入图集浏览器。单图上限 8MiB、文件总预算 128MiB，不将图片字节放入快照或扫描检查点。

商品快照增加 metadata、imagePath、metadataUpdatedAt、todayCheckCount、todaySuccessCount、todayFailureCount、monitoringMs。今日计数表示当前运行代际接受的完成检查结果，按北京时间完成日期记账。累计监控时长表示该商品实际处于监控计划中的时间，包含请求间隔和失败退避，暂停、计划外、停用、无可用出口、退出时停止累计，跨日及重启保留累计值。使用单调时钟计量增量并持久化毫秒；多出口不重复累计。异常退出允许损失最近一个短暂结算周期，离线时间不补记。

命令层提供快照、商品详情/历史、目录元数据刷新及现有监控操作，沿用核心事务与生命周期边界；前端负责渲染、格式化、筛选与局部动画。元数据、图片缓存、计时均不由前端维护。导入配置保留已有商品统计，新增商品等待元数据读取；清除历史与恢复默认的统计清理遵循统一规则。累计时长每约一秒结算，正常退出会结算尾段；异常退出及跨实例运行代际改变可损失约一个结算周期，界面按分钟展示。

## 二、测试场景

### 2.1 商品与缓存

检查相机、日记版、会员卡和无图片商品；价格为整数、小数、零、空和无效值；图片 URL、名称、价格发生变化以及可选字段消失；重复相同响应无元数据写入/无重复下载；图片 404、超时、超大文件、下载中取消选择、URL 再次变化、磁盘缓存被手工删除和 App 重启。所有图片失败均保持库存调度与通知功能。测试下载队列容量、文件总预算和缓存替换后无旧文件累积。

### 2.2 并发与操作

添加完成后立即开始监控，监控中再添加/取消/再次启用；重复添加在途时取消、删除或恢复默认；扫描与监控请求乱序返回；旧运行代际返回不能覆盖元数据、库存或统计；扫描暂停、取消、恢复和更换范围；目录接近容量上限时并发添加。所有添加/选择/元数据保存通过原子事务生效，返回值与最终快照一致。

### 2.3 统计与长运行

北京时间跨日有新请求和无新请求，失败请求计数，较旧请求排序拒绝；运行、暂停、继续、计划结束、计划开始、关闭窗口、退出与重启；多代理出口时长不重复；时钟前拨/后拨、月份边界；计数和累计毫秒接近数据库整数上限；导入配置失败回滚、导入后统计保持、清除历史和恢复默认一致清理。历史/通知/快照/扫描/缓存保持既有有界策略，消息筛选与浏览旧页不因实时检查跳回首页。

### 2.4 界面与端到端

同参考图尺寸检查网格比例、侧栏/操作栏/日志/抽屉位置、字体、颜色、图像完整性；真实长商品名、0/1/多商品、加载/失败/空状态、浅/深/System、窄窗口、200%文字缩放、键盘与减少动态效果。验证悬浮内容可通过焦点和点击访问、抽屉关闭与产品切换、日志日期/商品过滤、状态错误可复制；桌面资产路径与 CSP 实际加载。独立视觉审查必须以真实截图和原图在同一对照输入中判断。

先测上述可重现实例，再做持续监控；持续监控仅证明被观察时段的运行情况，无法证明一个月内所有外部服务故障都不存在。
