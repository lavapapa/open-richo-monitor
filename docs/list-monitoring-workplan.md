# 全站上架列表监控约定

监控核心提供全站上架列表与逐商品详情两种方案，两者共用观察归并、通知和持久化规则。

## 一、前提与契约

生产签名复用现有客户端；列表签名路径为 `/product/products`，查询参数保留附件的顺序及空值。列表出现表示 `isShow=1`，库存仍由 `stock` 判断，会员卡样本上架但库存为零。完整成功分页轮次未见的商品标记“本轮列表未见”，库存为未知，保留商品元数据。单页失败、业务异常、重复 ID 或超出轮次容量不能发布部分结果或推断未见。

每个出口一条串行列表轮次，每页共享全局请求限流与域冷却。请求 limit=20，一直读取到空页，避免服务端限制实际页长导致短页漏读。轮次容量 1000 件，最多 51 页；末页空页可证明恰好 1000 件的轮次完成。没有服务器快照或总数字段，因此无法消除翻页期间上下架变动带来的遗漏。全站返回的新商品仅参与对照，用户未选择的商品不会自动启用。

每件监控商品每次完整轮次增加一次检查计数；页数不增加商品检查次数。失败轮次每件增加一次失败检查，保留最近成功状态。计划、暂停、停用、恢复默认、导入、切换方案均沿用代际和事务边界；模式 A→B→A 也拒绝旧结果。元数据仅由本轮实际出现的商品更新，图片缓存保持既有策略。

## 二、验收场景

解析覆盖空数组、业务错误、数据形状变化、非法 ID/库存、重复 ID、超大响应、精确价格和可选元数据。分页覆盖不足一页、恰好整页、多页、服务端缩小 limit、重复页、后页超时、429、403、容量边界、页间商品移动。压力测试在本地运行，官方接口的实测有明确次数上限，遇到限流或访问拒绝停止。

生命周期覆盖零商品、运行时新增/取消、取消后重新启用、在途切换模式和 A→B→A、跨实例控制、暂停/继续、计划边界、重启、导入与恢复默认。缺席未知库存与库存零分别保存和展示；缺席到真实有货只触发一次库存通知，列表重复出现不重复通知。统计、消息、任务队列及元数据保持有界。

前端验证设置默认及保存、导入导出模式、空库存文案、错误弹窗和运行反馈；真实原生测试使用独立 App 标识与资料目录，保留正式配置。
