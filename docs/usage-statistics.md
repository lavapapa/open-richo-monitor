# 使用统计

## 用户选择

首次设置与“其他设置 → 数据与诊断”提供“分享使用统计（可选）”。首次引导默认勾选，完成引导后保存选择；再次进入引导优先沿用已保存的选择，尚无选择记录时默认勾选。开启后使用 PostHog Cloud 收集下表中的计数。关闭会取消在途统计请求、清空待发送事件并删除本机随机统计标识；再次开启会生成新的标识。恢复默认设置会关闭统计并保留这个关闭选择。

已经完成设置的旧安装，通过通用升级流程确认使用统计。勾选或取消勾选后确认都会保存结果；中途退出保留未确认项，下次启动继续。首次引导第三页显示一句说明和复选框，详细上报范围在升级提示与设置页展示；三处均提供 PostHog 官网的浏览器链接。

群名、聊天和账号 ID、商品名、凭据、通知正文、截图、点击轨迹和设备硬件信息均不进入事件。统计标识由随机数生成，保存在本机数据库。服务的网络连接仍会接触来源 IP；项目需关闭 IP 数据捕获，事件同时关闭 GeoIP 与个人资料处理。

## 事件与口径

| 事件 | 时机 | 用途 |
| --- | --- | --- |
| `app_active` | 同意后、应用后台启动及每小时 | 按随机安装标识计算活跃安装数 |
| `monitoring_started` | 成功开始、继续、重启监控，首次引导开启监控，后台启动恢复运行意愿 | 监控发起次数；等待计划开始也属于已发起 |
| `notification_configuration_changed` | 监控商品或通知对象数量变化后静默 5 秒 | 观察配置数量变化 |

每个事件携带系统、架构、应用版本、运行环境，以及监控商品数量、已配置/启用渠道数量、已发现群聊/私聊数量、启用渠道中选择的群聊/私聊接收位置数量和各平台的汇总计数。

人数口径为参与统计的安装数。同一人在多台电脑上使用会计为多个安装；关闭后再开启统计会使用新标识。群聊数分为“已发现接收位置”与“启用发送位置”，前者包括已发现但尚未勾选的群，后者排除未选择或停用的目标。同一群在不同安装或机器人中的配置分别计数。平台群聊发现能力不一致，发现数量以 App 已取得的信息为准。

监控发起次数与库存请求次数分开，计划跨日恢复、网络重连、通知重连均不增加发起次数。队列最多容纳 64 条统计事件，网络超时为 5 秒，拥塞或网络失败时丢弃统计。数据适合观察活跃趋势，不用作精确计费。后台关闭主窗口仍维持统计任务；退出应用时任务随 Core 一起结束。

## 后台配置

统计面板：[RichoMonitor · 使用统计](https://us.posthog.com/project/663820/dashboard/2208402)。使用作者的 PostHog 账号登录查看，面板保持私有。

`apps/desktop/usage-statistics.json` 保存接收端点与公开项目写入 Token。该 Token 允许事件写入，管理 API 密钥留在服务后台。版本由桌面包配置读取；dev 数据标记为 `development`，发行数据标记为 `production`。

PostHog 面板按 `environment = production` 筛选，活跃数使用 `distinct_id` 去重，监控次数使用 `monitoring_started` 事件数。当前群聊/私聊数应对每个安装取最后一次状态，再相加；重复状态快照直接求和会重复计数。关闭统计后服务端历史数据仍保留，历史接收位置数须配合“最近活跃安装”时间范围查看。

官方说明：[免费额度](https://posthog.com/pricing)、[事件 API](https://posthog.com/docs/api/capture)、[数据收集控制](https://posthog.com/docs/privacy/data-collection)。免费额度用完后服务停止接收超额事件，项目保持免费方案并保持未绑定付款方式。
